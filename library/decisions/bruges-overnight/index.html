在布鲁日增加过夜以保留清晨摄影

这条判断不属于某一次旅行；每一天只通过稳定 ID 引用它。

判断状态生效中创建时间 2026-08-14

判断

Europe 2026 在布鲁日过夜，并把清晨摄影作为这次停留的主要收益。

理由

过夜买到的是日游无法稳定取得的清晨摄影窗口；它能避开日间高峰并复用同一摄影机位的蓝调与日出条件。在 3A Cologne baseline 下代价显著下降：次日转场根特仅约二十六分钟，是全程最轻的一次移动。

依据

brugge-sunday-timetable

需要重新评估的条件

brugge-sunday-timetable

该记录解释为什么保留布鲁日过夜，而不复制最终行程本身。路线收益以清晨摄影的可达性衡量，不以“多去一个城市”衡量。如果引用事实变为 wrong 或 superseded，系统只派生 review_required，不会自动撤销或反转这项决定。

当前执行把 Rozenhoedkaai、Groenerei、Burg、Jan van Eyckplein 与 Markt 作为清晨主线；Minnewater / Begijnhof 只在前一晚已完成北区画面且额外步行余量充足时作为 alternative。未选择的 alternative 不创建 ShootSession。

2026-09-04：决策维持 active，晚数不变，但日期由 09-26 至 09-27 前移到 09-23 至 09-24。原本引用的 brugge-sunday-timetable 已 superseded——它描述的周日 Brugge 到 Bruxelles-Midi 衔接在新 baseline 中不存在。该 evidence 保留在 frontmatter 中而不是删除：它记录了本决策当初被批准时所依据的证据状态，删除会同时破坏 provenance 与 DecisionRecord 的 evidence 完整性。

新 baseline 下本决策的成本项已经改变：不再是“必须为国际列车衔接保留缓冲”，而是“布鲁日只有一次蓝调与一次清晨，没有第二天可补”。因此住宿位置要求（步行到 Rozenhoedkaai 十分钟内）比旧 baseline 更严格，而非更宽松。
