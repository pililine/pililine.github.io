跨旅行知识库

9月25日只保留共同清晨并延后选择 Ghent / Brussels 分支

这条判断不属于某一次旅行；每一天只通过稳定 ID 引用它。

判断状态已被取代创建时间 2026-08-14

判断

共同的 Graslei 清晨进入 active timeline；09:00 后的 Ghent 深度与 Brussels 半日都保持未选 option，前一晚按天气、体力和增加城市的意愿二选一。

理由

两个分支互斥，同时结构化会把候选误显示成确定行程。延后选择保留弹性，也避免为了增加城市牺牲恢复和晚间器材安全。

依据

没有外部依据，属于判断

需要重新评估的条件

没有触发条件

Option Ghent：适用于天气适合步行、希望降低移动量或需要恢复的情况；可深化 Gravensteen、Patershol 和水岸构图。

Option Brussels：适用于天气稳定、体力充足且明确愿意增加一个城市的情况；核心价值是 Grand-Place 夜间建筑与 Mont des Arts 城市轴线，往返应使用 Bruxelles-Central，避免在 Bruxelles-Midi 站外停留。

选择动作本身不会自动创建 records。只有正式选择后，才为相应分支添加 ShootSession / Operation；另一分支继续只保留 rationale 与 trigger。

2026-09-04 SUPERSEDED：3A Cologne baseline 取消了 09-25 这个条件日。根特压缩为一晚，09-25 清晨拍完 Graslei 后当天转场科隆；布鲁塞尔不再是“是否要多去一个城市”的可选分支，而是 09-21 至 09-23 的两晚 base，见 decision/brussels-two-night-base。

两个分支都已失去对应的时间窗口，因此本决策整体退役。它确立的原则——互斥分支在正式选择前不得同时结构化——继续有效，并在新 baseline 中被 09-25 的路线选择与 09-21 的蓝调机位分别沿用。
