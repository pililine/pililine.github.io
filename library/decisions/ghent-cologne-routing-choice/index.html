2026-09-25 根特到科隆选择经布鲁塞尔换乘的路线

这条判断不属于某一次旅行；每一天只通过稳定 ID 引用它。

判断状态生效中创建时间 2026-09-04

判断

09-25 使用经布鲁塞尔换乘一次的路线；经安特卫普直达 ICE 的路线保留为 fallback，不创建 active Operation。

理由

经布鲁塞尔的路线在每个运营维度上都不劣于备选，并在两项上决定性领先——快约三十到五十分钟，班次密度约为七倍。当天以在另一个国家办理不可退住宿的入住结束，因此接续失败的代价才是决定性变量：在已选路线上是等待约一小时，在备选路线上可能是数小时甚至次日。

依据

ghent-cologne-routing-via-brussels · antwerp-cologne-direct-ice-2026-09 · cologne-ostend-ice-summer-only

需要重新评估的条件

ghent-cologne-routing-via-brussels · antwerp-cologne-direct-ice-2026-09

fallback 不只是更慢的同一条路

经安特卫普的直达 ICE 走 Brussels Airport 而非布鲁塞尔市区车站，因此它是一条真正独立的退路：当 Bruxelles-Midi、Nord 或 Central 因罢工或施工瘫痪时，已选路线失效而它不受影响。这是它作为 fallback 而非单纯次优选项的理由。

启用条件：布鲁塞尔市区车站瘫痪或封站；或已选路线的布鲁塞尔到科隆区间售罄、价格失控。

启用前提：该服务每方向每日仅两班，必须在 09-24 晚上就查好当日两个发车时刻并记录，次日临时切换来不及。

关于 Bruxelles-Midi 的风险判断

手册中“Bruxelles-Midi 是全程风险最高车站”的判断只针对夜间。09-25 的换乘发生在中午前后，该判断不适用，不构成选择 fallback 的理由。

未选分支不结构化

依保守分支规则，fallback 路线不创建 active Operation，只保留 rationale 与触发条件。已选路线的具体车次同样仍未确认，transport/2026-09-25-ghent-cologne 的时刻为规划包络而非已订班次。
